# WireGuard homelab

Набор скриптов, конфигураций и инструкций для развертывания WireGuard VPN и экспериментов с маршрутизацией через Cloudflare WARP. В репозитории также собраны средства управления VPN: веб-интерфейсы, Telegram-бот и Phobos — автоматизация соединения между VPS и роутерами с обфускацией трафика.

Компоненты предназначены для отдельных сценариев. Единого установщика для всего репозитория нет; конфигурации содержат параметры конкретных сетей и требуют адаптации перед использованием.

## Требования

- Linux-сервер с правами `root` или доступом через `sudo` для установки и настройки сети.
- Доступ в интернет для загрузки пакетов и внешних зависимостей.
- Доступный UDP-порт для WireGuard, разрешенный также в firewall хостинга или на внешнем маршрутизаторе.
- Для WARP-сценариев — уже настроенный WireGuard и согласованные имена интерфейсов, подсети и правила маршрутизации. Скрипты этих каталогов ориентированы на системы с `apt`.
- Дополнительные зависимости зависят от компонента: Docker для приведенных примеров WGDashboard, Python и PostgreSQL для бота, Entware на клиентском роутере для Phobos.

Поддерживаемые ОС базовый установщик проверяет при запуске. Требования отдельных компонентов приведены в их документации.

## Базовый запуск WireGuard

Выполните из корня репозитория на целевом Linux-сервере:

```bash
sudo bash wireguard-install.sh
```

Установщик запросит внешний адрес сервера, сетевой интерфейс, адреса VPN, UDP-порт и DNS для клиентов, затем установит WireGuard и предложит создать первого клиента. Путь к клиентской конфигурации будет показан в терминале; ее можно импортировать в приложение WireGuard или использовать выведенный QR-код.

Повторный запуск той же команды открывает меню управления установленным сервером: добавление, просмотр и отзыв клиентов, а также удаление WireGuard.

Для проверки состояния, если интерфейс назван `wg0` и используется systemd:

```bash
sudo wg show
sudo systemctl status wg-quick@wg0
sudo journalctl -u wg-quick@wg0 -n 50
```

Если при установке выбрано другое имя интерфейса, замените `wg0` в командах.

## Дополнительные сценарии

### Выход через Cloudflare WARP

В репозитории есть несколько подходов: профиль WireGuard через [wgcf](wgcf/setup-wgcf-warp.sh), [сетевое пространство имен](tunnel_warp_wireguard/install.md), [Squid](proxy_squid_warp_cli/install.md) и [redsocks](redsocks_warp/install.md). Выберите один вариант и изучите его скрипты и конфигурации перед применением: они не рассчитаны на последовательный запуск как этапы одной установки.

В `wgcf/setup-wgcf-warp.sh` заданы клиентская подсеть `10.77.33.0/24`, входящий интерфейс `wg0` и исходящий `wgcf`; скачивается бинарник для Linux amd64. Скрипт ожидает существующий `/etc/wireguard/wg0.conf` и установленную команду `wg-quick`. Эти параметры нужно сверить с вашим сервером.

### Phobos: VPS и роутеры

Начните с [описания Phobos](Phobos/README.md), [серверной документации](Phobos/docs/README-server.md) и [клиентской документации](Phobos/docs/README-client.md).

Точка входа полной установки — `Phobos/server/scripts/vps-init-all.sh`. Она последовательно устанавливает зависимости, собирает `wg-obfuscator`, настраивает WireGuard и обфускатор, запускает HTTP-сервер выдачи пакетов и устанавливает меню `phobos`. Через меню можно управлять сервисами и клиентами и получать команды установки для роутеров.

### Telegram-бот и веб-интерфейс

Установка бота и параметры подключения к Telegram, PostgreSQL и WireGuard описаны в [его README](tg_bot/wireguard-bot/README.md). В этой документации проект отмечен как неподдерживаемый.

Примеры запуска WGDashboard через Docker находятся в [ui/install.md](ui/install.md).

## Особенности конфигураций

- Перед применением замените адреса, ключи, порты, подсети и имена внешних интерфейсов на значения вашего сервера. Секретные ключи и токены храните вне публичного репозитория.
- Сохраните текущие конфигурации WireGuard и firewall перед запуском сетевых скриптов. В частности, `proxy_squid_warp_cli/setup-squid-routing.sh` очищает правила iptables и устанавливает политики `INPUT DROP` и `FORWARD DROP`, разрешая SSH на порту `22`.
- `tunnel_warp_wireguard/setup-wg-warp.sh` удаляет прежнее пространство имен `warpns` и содержимое `/var/lib/cloudflare-warp/` при подготовке окружения.
- В `ui/install.md` есть команда массового удаления Docker-контейнеров, образов, томов и сетей. Она не является обязательным шагом установки WGDashboard.
- WARP- и прокси-конфигурации представлены как рабочие материалы для экспериментов; наличие примеров не подтверждает работоспособность всей схемы на конкретном сервере. Проверяйте маршруты, DNS и прохождение трафика после настройки.
